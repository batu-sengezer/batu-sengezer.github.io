An FPGA Project From My Undergrad: Cargo Distribution Conveyor System

A term project from Bilkent's Introduction to Digital Design course: a small FPGA controlled conveyor system for storing and distributing cargo packages, built on a Basys 3 board with ultrasonic sensors and DC motors.

This is one of the older things I've built, from EEE-102, Introduction to Digital Design, back in undergrad at Bilkent. It's also one of the courses I did best in (A-), so I still think back on it every now and then. I figured it's worth writing up properly since the video has been sitting online for years without any real explanation next to it.

The assignment

The course project was fairly open ended: build something using the FPGA board that actually controls a physical process, using what we'd learned about digital logic design that semester. I ended up going with a small storage and distribution system for aerial cargo, packages come in, get staged for pickup, and then get moved into storage once someone takes them. Half the fun of picking that scenario was that it gave me an excuse to build two conveyor belts.

What it does

When you activate the system, a package gets released and a green LED turns on to show it's ready for pickup. Once the package is taken from the pickup point, the system moves it onward into the storage section of the model. All of this, release, signaling, and the belt movement, is handled by logic running directly on the FPGA. There's no microcontroller anywhere in the design, it's all done through the digital logic itself.

The hardware

The board is a Digilent Basys 3, which has a Xilinx Artix-7 XC7A35T-1CPG236C FPGA on it. That's what runs the whole control sequence as actual digital logic rather than code running on a processor.

For sensing package position at each stage (distribution, pickup, storage), I used three HC-SR04 ultrasonic range sensors. These work by sending out a pulse and timing how long it takes for the echo to come back. On the FPGA side that meant generating the trigger pulse and measuring the echo pulse width in hardware, then turning that into a simple present or not present signal for the rest of the logic to use.

The two DC motors that drive the conveyor belts couldn't be wired straight into the FPGA's pins, the current draw is too much for the board's I/O to handle safely. So there's an L298N motor driver sitting in between, which takes the logic level signals from the FPGA and switches the higher current going to the motors. That's also what let me control each belt's direction independently.

Four LEDs handle status feedback around the system, mainly the "package ready" indicator, plus a couple of others for different states.

Looking back on it

I haven't touched VHDL or FPGA design since this course, my work these days is mostly on the software side, real time C/C++ and more recently embedded ML. But this project is where I first had to think about timing at the gate level, and about how a design that looks clean on paper still has to survive an actual motor driver and a sensor reading that doesn't always come back clean. Some of that thinking has stuck with me even outside of FPGA work specifically.
